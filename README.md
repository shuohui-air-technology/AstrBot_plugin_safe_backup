# AstrBot 自动化安全冷备份插件

![python](https://img.shields.io/badge/python-3.12%2B-blue) ![astrbot](https://img.shields.io/badge/astrbot-%3E%3D4.26%2C%3C5-green) ![platform](https://img.shields.io/badge/platform-Windows-blue) ![license](https://img.shields.io/badge/license-MIT-gray) ![version](https://img.shields.io/badge/version-v0.1.0--beta-orange)

A cold backup plugin for security-conscious AstrBot users, efficiently and cautiously backing up your sensitive data.

> `v0.1.0-beta`：目前仅支持 AstrBot `>=4.26,<5` 与本地 Windows 冷备份。请先进行测试，再用于重要数据。

## 安装与初始化

### 1. 安装插件

可任选一种方式：

- 在 AstrBot 插件市场搜索并安装“**AstrBot 自动化安全冷备份插件**”；
- 下载项目 Release ZIP 中提供的插件安装包，并在 AstrBot 的插件安装界面选择该 ZIP。

安装后重新加载插件或重启 AstrBot。插件被加载时不会创建备份、计划任务或目标目录。

### 2. 一键初始化

在 AstrBot 管理员聊天中发送：

```text
/safe_backup setup
```

首次使用不必填写路径。插件会为当前 AstrBot 实例计算一个独立的本地默认备份目录，并且只接受一个不存在或完全为空的目录。目录中一旦发现陌生文件、旧状态或未知归档，就会停止，不会接管或清理它。

初始化会依次验证兼容性、目标目录和计划任务身份；通过后才创建本插件专属任务并启动一个**只等待当前 AstrBot 自然退出**的一次性等待器。它不会关闭、暂停、重启或强杀 AstrBot。

完成初始化后可以继续正常使用 AstrBot。等你按平常方式退出 AstrBot 后，等待器确认进程已退出，首次备份便会自动开始；不需要等到一个模糊的固定时间点。

### 3. 查看首次备份

每次实际备份尝试都会打开一个可视终端窗口，显示安全预检、数据清点、复制、SQLite 隔离处理、ZIP 生成、归档验证与发布等进度。成功时窗口会显示：

```text
备份成功
```

成功窗口会在 30 秒后自动关闭；失败窗口会保留 120 秒，期间可按任意键提前关闭。已在本周成功、只做状态检查的计划触发不会弹出窗口。

首次备份完成后，日常状态可用以下命令查看：

```text
/safe_backup status
/safe_backup check
/safe_backup history
/safe_backup verify latest
```

## 主要功能

- AstrBot 的源数据只作普通共享读取；不会修改、移动、删除、修复、解锁或恢复任何源文件时间戳。
- 不停止、暂停、重启或强杀 AstrBot；无法确定它已停止时，本次备份失败关闭。
- 尝试完整收录 AstrBot `data`：配置、插件、插件数据、知识库、附件、索引、数据库、空目录与未来新增的普通文件。
- 源 SQLite 仅作为普通文件读取；只有复制到备份目标的隔离副本才会进行规范化和 `integrity_check`。
- 两轮清点、文件身份、大小、修改时间和 SHA256 检查会捕捉备份中的变化；关键变化、占用或布局漂移不会静默生成正式包。
- ZIP 发布前会检查路径安全、CRC、清单 SHA256、数据库完整性与恢复布局。
- 默认不会联网、上传、遥测、使用 NAS/UNC 或自动恢复。历史归档仅按下文的严格归属与完整性门禁自动保留最多 5 份。

### 可选的 NapCat 配置备份

NapCat 功能默认关闭，普通 AstrBot 用户无需配置它。只有在插件设置中明确开启并填写本地根目录后，才会备份经过版本元数据验证的配置白名单。

该可选包不包含程序二进制、缓存、日志、临时文件、运行数据库或账号运行数据。NapCat 版本或目录布局变化时会暂停备份并等待人工确认，不会自行猜测新版目录。

## 设置项

默认设置已经能完成首次初始化。需要调整时，可在插件设置中修改：

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| `destination_path` | 留空 | 使用插件生成的本地专属目录；也可填写源目录以外的本地绝对空目录。 |
| `retention_count` | `5` | 最多保留的可信归档数。只会清理本插件权威状态已绑定且再次完整验证通过的旧归档。 |
| `schedule_weekday` | `Sunday` | 每周首次尝试日。 |
| `schedule_time` | `12:00` | 本地时间，使用 `HH:MM`。 |
| `napcat_enabled` | `false` | 是否启用可选 NapCat 配置包。 |
| `napcat_root` | 留空 | 仅启用 NapCat 时填写本地绝对路径。 |

配置改动不会自动修改 Windows 计划任务，避免插件在后台改变系统设置。插件代码更新或替换后，任务绑定的插件摘要也可能发生漂移；先运行 `/safe_backup status`，若显示漂移，确认无误后由管理员显式执行：

```text
/safe_backup task update
```

该命令只会更新身份、描述和动作均匹配本插件的任务，并在任务复核通过后立即同步计划参数和状态绑定；它不会立即启动备份，也不会伪造已有归档的成功记录。身份不匹配或状态不可信时会拒绝操作；若提示结果不确定或已隔离，请先运行 `/safe_backup status` 复核，不要反复重试。

## 调度与失败重试

计划任务以当前 Windows 用户、最低权限运行，忽略重叠启动，不唤醒电脑，也没有强制结束超时。

在所设定的星期先尝试一次；如果失败，在本周期的其余每天重试一次，直到成功或本周期结束。一旦本周已有完整成功归档，之后的每日触发只检查状态并安静退出。失败不会删除旧归档，也不会为了提高成功率关闭 AstrBot。

## 管理命令与卸载

| 命令 | 作用 |
| --- | --- |
| `/safe_backup status` | 显示脱敏状态、是否配置漂移、NapCat 是否启用。 |
| `/safe_backup check` | 仅检查路径、配置和状态归属；不读取数据库、不创建目录。 |
| `/safe_backup history` | 显示小型脱敏运行记录。 |
| `/safe_backup verify latest` | 在后台线程验证最新的受管归档，不读取源数据。 |
| `/safe_backup task update` | 显式更新经过身份核验的本插件任务。 |
| `/safe_backup task remove` | 显式移除经过身份核验的本插件任务；不删除归档、状态或插件文件。 |

卸载插件前，请先发送 `/safe_backup task remove`。卸载插件不会自动删除计划任务，以免无意中改变系统中仍在使用的任务。

## 归档、验证与恢复

备份归档未加密，可能包含 API 密钥、令牌、passkey、插件配置和聊天数据。请保存到只有自己可访问的本地位置，不要上传、提交到 Git 或放进公共共享。

本插件不提供自动恢复，因为恢复会覆盖数据。建议的人工恢复流程是：

1. 先使用 `/safe_backup verify latest` 验证归档；
2. 解压到新的空目录，检查 `backup-manifest.json` 与 `RESTORE-NOTES.txt`；
3. 安装兼容版本的 AstrBot，并在隔离环境进行测试；
4. 确认相关程序已正常退出后，再由管理员人工替换数据；替换前另存当前数据副本；
5. 若验证失败，停止新环境并回退到替换前副本。

## 已知问题：可能导致备份失败

以下是正常使用中可能遇到的失败条件。它们不会被当作成功静默通过：

- 备份触发时 AstrBot 仍在运行，或 Windows 无法可靠确认进程状态；
- 源文件、SQLite/WAL 家族、插件数据或配置在两轮检查之间发生变化；
- 源文件被其他程序占用而无法用共享只读方式读取；
- 目标目录不是空目录，或者已有状态、owner、归档、重解析点或文件系统能力不符合要求；
- 可选 NapCat 的版本、元数据或配置白名单在备份期间改变；
- 目标磁盘可用空间不足，或归档最终验证未通过；
- 路径、插件包、计划任务或状态的身份核验无法完成。

遇到这些情况，请保留现场并检查 `/safe_backup status` 与终端中的固定提示；不要手工接管或删除隔离内容。
针对某些极端的同账户恶意攻击场景，由于这些情境被认为不容易在实际使用场景中遇到，且对他们的修正是困难且易引发其他重大问题的，故将这些统一记录在 [SECURITY.md](SECURITY.md)，而没有做实际修复

## 隐私与安全边界

源端“严格只读”只针对 AstrBot（以及用户启用时的 NapCat）数据；备份目标会写入归档、状态、日志和隔离副本。该项目的同盘本地备份不能防磁盘/卷损坏、格式化、勒索软件或同一 Windows 账户下的恶意程序。

自动保留默认上限为 5 份。新备份完成、正式 ZIP 通过完整验证并且成功状态已经持久提交后，插件才会为超出上限的旧归档生成删除授权；删除前还会重新核对 owner、权威状态日志、源指纹、归档 SHA-256、文件身份、单硬链接及完整 ZIP 内容。任何一步不确定都会停止自动清理并保留文件。外来、损坏、被替换、硬链接或无法证明归属的 ZIP 永不自动删除，因此目录中的实际 ZIP 数可能暂时超过配置值。

当前 run 的 staging 只会在两轮目录清点与完整身份登记（本次运行记录、随机 UUID 路径与对象身份令牌）完全一致时清理。任一不一致或清理失败都会失败关闭，敏感 quarantine 会保留并报告，历史、陌生或无法证明归属的内容绝不清理。

普通身份不匹配、状态异常和自然并发都会失败关闭。极端情况下，同一 Windows 账户下的恶意程序可在检查之后发起精确 TOCTOU 或替换祖先 junction；这不属于普通使用的防御边界，详见 SECURITY。`setup`、update/remove 均为用户显式操作。

所有测试只使用合成目录。开发、测试和发布流程不应访问真实 AstrBot、NapCat、计划任务或备份目录。
